# 2026-08-20 — inicialización del repositorio

## Contexto

Primera sesión del proyecto. Objetivo: dejar la estructura documental y de
build lista (AGENTS.md, ADRs 0001–0003 como placeholders formales, esquema de
`docs/sessions/` y `docs/format/`), sin escribir todavía código de protocolo
Tailscale. El proyecto reimplementa selectivamente el enfoque de
`alfs/tailscale-iot` (cliente Tailscale mínimo para ESP32) en C puro sobre
ESP-IDF, sin ESPHome, priorizando seguridad y estabilidad por sobre todo lo
demás según lo fijado por el usuario.

## Cambios

- Creado `AGENTS.md` con: alcance real del proyecto, modelo de amenaza (física
  y remota con igual prioridad), reglas de C no negociables, estructura de
  repo, política de vendoring, y proceso de trabajo esperado de opencode.
- Creada estructura de directorios: `main/`, `components/tsnode/`,
  `third_party/`, `tests/{unit,protocol_vectors}/`, `docs/{adr,sessions,format}/`.
- Creados `docs/adr/0000-template.md` (plantilla) y tres ADRs iniciales:
  - `0001-record-architecture-decisions.md` (aceptado) — fija que este proceso
    de ADRs se usa desde el día uno.
  - `0002-threat-model.md` (propuesto, placeholder a completar) — formaliza el
    modelo de amenaza de AGENTS.md §2 en decisiones concretas.
  - `0003-key-storage-strategy.md` (propuesto, placeholder a completar) —
    estrategia de NVS/flash encryption y alcance de Secure Boot v2.
- Creados `docs/format/c-style.md`, `docs/format/commits.md`,
  `docs/format/adr-process.md`.

## Decisiones de seguridad tomadas o revisadas

Ninguna decisión técnica concreta todavía — ADR-0002 y ADR-0003 quedan
deliberadamente en estado `propuesto` como placeholders. Se fijó el *proceso*
(ADR-0001, aceptado): ninguna decisión de arquitectura, claves, o superficie
de ataque se implementa sin ADR previo. Se decidió explícitamente NO escribir
código de protocolo en esta sesión hasta que ADR-0002 y ADR-0003 tengan
contenido real, no solo la estructura.
